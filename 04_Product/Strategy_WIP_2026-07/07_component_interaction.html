Which part talks to which — and how

PushApp has exactly two ways components communicate. Inside the app, engines never call each other directly — they emit and react to events on the EventBus. To the outside, the app reaches every backend only through a gateway. These two diagrams show the real connections and what travels along each one.

① Inside the app — engines talk through the EventBus

No engine imports another. Each arrow is a real event: an engine emits it (arrow into the bus) and other engines react to it (arrow out to them). This is why a new engine can plug in without touching the others. StepMissed ★ is the keystone — it's the one event nothing emits yet.

② To the backend — the app talks only through gateways

Every outside call crosses a vendor-isolated gateway (interface + a Null fallback + a feature flag). Flip a flag off and that gateway returns nothing — which is exactly why the app runs fully offline at $0. Note Journey: it talks to no backend at all — it persists to the on-device Repository.
