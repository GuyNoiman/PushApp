## 3. Standing context

### 3.1 The fingerprint rule
See §0. `df6c2127…` is build 3. Anything native moves it.

### 3.2 A dev runtime older than the dependencies cannot render them
`Unimplemented component: ViewManagerAdapter_…` means the binary on the device predates the
dependency. Not a code bug, and deliberately not worked around.

### 3.3 Two dev servers race on the generated router types
`.expo/types/router.d.ts` is generated, gitignored, and gets corrupted when two `expo start`
processes run on the same folder. If `tsc` reports syntax errors inside it, that is why — delete it
and let Expo regenerate.

### 3.4 The tab bar exists twice
`app-tabs.tsx` and `app-tabs.web.tsx` are kept in sync BY HAND.

### 3.5 Nobody's name in shipped copy
`src/i18n/__tests__/noPersonalData.test.ts` sweeps every resource file and fails if a development
identity ships.

### 3.6 A release build cannot invent data
The demo seed and the simulated identity are gated on `__DEV__` as well as their env vars.

### 3.7 Two standing instructions about the founder
**Ask complete questions** — never use a term without defining it in the same message. **He wants to
see, not read** — render options rather than describing them.

### 3.8 The Tool Addition Protocol governs every tool
`04_Product/Tool_Addition_Protocol.md`. A tool declares what it teaches us, the smallest summary that
carries it, who may read it with a reason each, and when it goes stale. "It influences nothing" is a
valid contract; leaving it unanswered is not.
