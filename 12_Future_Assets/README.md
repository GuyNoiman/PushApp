# Future Assets — preserved work that must not take up space in the build

> **Nothing here is deleted.** Everything in this folder is real, finished work that is staged
> **Future** and therefore has no place in a shipping build. It stays in git so it can come back
> intact. `CLAUDE.md §3.3`: *the vision never shrinks — move it later, never delete it.*

## Why this folder exists

Founder rule, **2026-08-17**:

> *"Anything Future should not be part of the project and therefore not part of the build. It
> should live in a different, external folder. From the next build onward, nothing Future should
> take up space."*

The trigger: the first EAS build uploaded a **258 MB** project archive. `app/assets/` alone was
**63 MB**, almost all of it 3D creature assets for the **Buddy** — a feature deferred to Future by
Decision Log **D45** (*Buddy / avatar DEFERRED to Future; the coach is the MVP's central
user-facing entity*), with no reachable surface anywhere in the app.

EAS uploads the **`app/` directory**. This folder sits at the **repository root**, outside `app/`,
so nothing here is uploaded, bundled, type-checked, linted or tested — while git still keeps every
byte. The 3D pipeline in particular is genuine engineering (an ingest tool plus a generated species
registry), so parking it somewhere untracked was never an option.

## Layout — a one-for-one mirror of `app/`

The tree under `12_Future_Assets/app/` mirrors the real `app/` tree exactly. That is deliberate:
**restoring any file is a straight reverse `git mv`**, with no path guesswork.

```
12_Future_Assets/app/
  assets/buddies/                     20 creature packages + _sdk (≈62 MB)
  src/app/(tabs)/buddy.tsx            the Buddy route
  src/app/shop.tsx                    the Shop route
  src/components/buddy/               BuddyCard · BuddyInventory · BuddyScene · EvolveReveal · stageFaces
  src/components/buddy3d/             BuddyView (the three/expo-gl renderer) · polyfills · upng-js types
  src/core/buddies/registry.generated.ts
  src/i18n/resources/{en,he}/buddy.json · shop.json
  src/archive/screens/                the four screens archived on 2026-08-14
  tools/ingest_creature.py            the creature-package ingest pipeline
  tools/optimize_buddy.py             the GLB/texture optimiser
```

## What moved, on 2026-08-17

| What | Was at | Why it could move |
|---|---|---|
| **Buddy 3D assets** (20 species + `_sdk`) | `app/assets/buddies/` | Loaded only by `registry.generated.ts`, which moved with them. ≈62 MB — the entire point of the exercise. |
| **`buddy.tsx`** | `app/src/app/(tabs)/buddy.tsx` | Hidden from the tab bar (`href: null`) but **any** file under `src/app/` is a live deep-linkable route under file-based routing — hiding it was never enough. Same lesson as `buddy3d-spike.tsx` on 2026-08-14. |
| **`shop.tsx`** | `app/src/app/shop.tsx` | Same: a registered `<Stack.Screen>` with no entry point. Coins / faux-currency are out of the mature coach direction. |
| **`components/buddy/*`** (5 files) | `app/src/components/buddy/` | Imported only by `buddy.tsx` and by each other. **`BuddyAvatar.tsx` did NOT move — see below.** |
| **`components/buddy3d/*`** | `app/src/components/buddy3d/` | The only place `three` / `@react-three/fiber` / `expo-gl` / `upng-js` were imported. |
| **`core/buddies/registry.generated.ts`** | `app/src/core/buddies/` | Generated by `ingest_creature.py`; `require()`s every GLB and texture. |
| **`buddy` + `shop` i18n namespaces** | `app/src/i18n/resources/{en,he}/` | Used by the moved screens only. Both removed from `NAMESPACES` and `resources` in `src/i18n/index.ts`. |
| **`src/archive/screens/`** | `app/src/archive/` | Already outside the router tree and excluded from tsc/eslint/jest — but still inside `app/`, so still uploaded. |
| **`tools/ingest_creature.py`, `tools/optimize_buddy.py`** | `app/tools/` | Serve the Buddy 3D pipeline and nothing else. `app/tools/` is now empty and gone. |

### Dependencies removed from `app/package.json`

`@react-three/fiber` · `three` · `@types/three` · `expo-gl` · `upng-js` — all five existed solely
for `BuddyView.tsx`. Verified with `npm ls` that nothing else in the tree required them (`expo-gl`
and `three` were needed only by `@react-three/fiber`, which also went). `expo-asset` was **kept**:
`expo` itself depends on it and it is a config plugin in `app.json`.

### What deliberately stayed in `app/`

Anything still reachable from live code stays — a smaller win beats a broken app.

- **`src/components/buddy/BuddyAvatar.tsx`** — a pure `react-native-svg` component with no image
  assets. `src/components/explore/ExploreCards.tsx` still imports it for the Explore marketplace
  cards, so it is shared, not orphaned.
- **`BuddyEngine`, `config/buddyStages.ts`, and the `Buddy` state** — wired into `AppCore`.
- **`ShopEngine`, `config/shopItems.ts`, and the `ownedCosmetics` state** — wired into `AppCore`.
  Only the Shop *screen* moved; the engine underneath it did not.
- **`MissionEngine`, the `MISSIONS` config and `MissionsState`** — wired into `AppCore`; Home reads
  them for collectable rewards. Moving them would break the app.
- **`metro.config.js`** still registers `.glb` in `assetExts`. Harmless with no `.glb` left in
  `app/`, and left in place so a restore is one step shorter.

## Restoring something

Restoring the **whole Buddy feature**, from `/Users/guynoiman/Documents/PushApp`:

```bash
git mv 12_Future_Assets/app/assets/buddies                   app/assets/buddies
git mv 12_Future_Assets/app/src/core/buddies                 app/src/core/buddies
git mv 12_Future_Assets/app/src/components/buddy3d           app/src/components/buddy3d
git mv 12_Future_Assets/app/src/components/buddy/BuddyCard.tsx      app/src/components/buddy/
git mv 12_Future_Assets/app/src/components/buddy/BuddyInventory.tsx app/src/components/buddy/
git mv 12_Future_Assets/app/src/components/buddy/BuddyScene.tsx     app/src/components/buddy/
git mv 12_Future_Assets/app/src/components/buddy/EvolveReveal.tsx   app/src/components/buddy/
git mv 12_Future_Assets/app/src/components/buddy/stageFaces.ts      app/src/components/buddy/
git mv "12_Future_Assets/app/src/app/(tabs)/buddy.tsx"       "app/src/app/(tabs)/buddy.tsx"
git mv 12_Future_Assets/app/src/i18n/resources/en/buddy.json app/src/i18n/resources/en/buddy.json
git mv 12_Future_Assets/app/src/i18n/resources/he/buddy.json app/src/i18n/resources/he/buddy.json
mkdir -p app/tools && git mv 12_Future_Assets/app/tools/ingest_creature.py app/tools/
git mv 12_Future_Assets/app/tools/optimize_buddy.py app/tools/
```

then, in `app/`:

1. `npm install @react-three/fiber three @types/three expo-gl upng-js` — check the versions match
   the Expo SDK in use (`npx expo install --check`); the versions that worked were
   `@react-three/fiber@9.6.1`, `three@0.180.0`, `@types/three@0.180.0`, `expo-gl@16.0.10`,
   `upng-js@2.1.0`.
2. `src/i18n/index.ts` — re-add the `buddy` import, the `'buddy'` entry in `NAMESPACES`, and
   `buddy: enBuddy` / `buddy: heBuddy` in `resources`.
3. `src/components/app-tabs.tsx` — re-add `<Tabs.Screen name="buddy" options={{ href: null }} />`,
   or give Buddy a real tab.
4. Remove `*.glb` (and any other format you need) from `app/.easignore`, or the assets will be in
   the repo but **missing from the build**. This is the easiest step to forget.
5. Give it a real entry point, and update `04_Product/UX/Archived_Screens.md`.

**Shop** additionally needs `git mv 12_Future_Assets/app/src/app/shop.tsx app/src/app/shop.tsx`,
its two `shop.json` files, the `shop` namespace back in `src/i18n/index.ts`, and
`<Stack.Screen name="shop" options={{ presentation: 'modal' }} />` back in `src/app/_layout.tsx`.
Per the 2026-08-14 founder decision, a revived screen needs a **surface PRD first**.

**`src/archive/screens/`** was previously excluded from the type-check (`tsconfig.json`), the lint
program (`eslint.config.js`) and the test run (`package.json` › `jest.testPathIgnorePatterns`).
Those three exclusions were removed when the folder left `app/`; moving it back means putting them
back, or the archived screens will fail the build. Its own `README.md` moved with it and carries
the per-screen detail.
