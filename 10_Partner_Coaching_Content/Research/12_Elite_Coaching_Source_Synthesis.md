# 12 — Elite Coaching Source Synthesis

**Version:** 0.6-draft  
**Owner:** Content / coaching characterization  
**Purpose:** Distill useful ideas from behavior science, established coaching frameworks, elite coaches, and influential practitioners into a coherent PushApp coaching method. This is a source review, not a requirement to imitate any individual coach.

## 1. The rule for using external ideas

PushApp should not become a collage of famous frameworks. Every external idea must answer four questions:

1. **What useful problem does this idea solve?**
2. **When is it relevant in a PushApp conversation?**
3. **What is the evidence level?**
4. **Does it fit framework-not-content, user ownership, safety, and real-life action?**

Each idea receives one status:

- **KEEP** — strong fit; can become a stable PushApp principle or move.
- **ADAPT** — useful insight, but must be narrowed/reframed for PushApp.
- **REJECT AS CORE** — interesting or popular, but insufficiently supported, too broad, too prescriptive, or incompatible with the product philosophy.

## 2. Evidence weighting

When sources conflict, prioritize them in this order:

1. **Research evidence:** meta-analyses, systematic reviews, primary research, mature psychological theory.
2. **Professional coaching frameworks:** established coaching competencies/methods with broad professional use.
3. **Elite practitioner patterns:** methods repeatedly used by respected coaches, especially when they converge with research.
4. **Popular frameworks:** useful heuristics from authors/speakers; never treated as psychological facts unless independently supported.

A famous coach is a source of **practice hypotheses**, not proof.

# 3. Source-by-source synthesis

## 3.1 Tony Robbins — purpose, result and momentum

### What is useful
Tony Robbins' RPM framework explicitly connects **Result → Purpose → Action**. His current official materials describe RPM around defining the result, connecting it to why it matters, and identifying actions that move it forward.

### PushApp judgment
**ADAPT.**

Useful for PushApp:
- do not let a Journey become a disconnected to-do list;
- reconnect action to a meaningful Dream when motivation becomes abstract;
- once understanding is sufficient, move decisively from analysis to action;
- create momentum rather than continuing conversation for its own sake.

Adaptation required:
- replace the default idea of **“massive action”** with **“minimum meaningful action”** or **“right-sized momentum action.”** PushApp optimizes for sustainable persistence, not intensity.
- “state management” can inspire attention to readiness/energy, but should not become a diagnostic psychological model or a set of unsupported claims.

### Do not import as core
- NLP-based mechanisms as factual psychological explanations;
- “Six Human Needs” as a diagnostic taxonomy of users;
- pressure, spectacle, or high-arousal motivation as the default coaching style;
- the assumption that larger action is inherently better.

### PushApp move extracted
**PURPOSE-TO-ACTION:** when a user knows what they want but the plan feels mechanical, briefly reconnect the next action to the user-owned reason, then move forward.

**Source type:** practitioner framework.

## 3.2 Simon Sinek — Why as a compass, not a ritual

### What is useful
Sinek's Start With WHY framework treats purpose/cause/belief as a source of direction. His more recent material also frames WHY as a decision filter rather than merely a slogan.

### PushApp judgment
**ADAPT.**

Useful for PushApp:
- Dream should preserve the broader reason a Journey matters;
- purpose can help choose between competing goals or actions;
- when a user drifts into “should,” the coach can check whether the goal still connects to a user-owned reason.

Adaptation required:
- do not ask “why?” repeatedly;
- do not force every user to articulate a grand life purpose;
- a practical, modest reason is enough;
- purpose is useful only if it changes focus, commitment or action.

### PushApp move extracted
**PURPOSE FILTER:** when several options compete, ask which one better serves what the user actually wants to move toward.

**Source type:** practitioner/leadership framework.

---

## 3.3 James Clear — systems, environment, small actions, identity

### What is useful
Clear popularizes several ideas highly compatible with behavior-change research: focus on systems rather than outcomes alone, design the environment to make behavior easier, start small, use stable cues, and return quickly after lapses.

His “identity-based habits” framing is also useful as a motivational lens: repeated actions can become evidence about the kind of person a user is becoming.

### PushApp judgment
**KEEP / ADAPT.**

**KEEP:**
- system/environment before willpower;
- reduce friction;
- make recurring behavior easy enough to repeat;
- stable cues/context;
- do not overreact to one miss.

**ADAPT identity:**
- never tell a user what their identity is;
- never turn “identity” into a hidden diagnosis;
- use completed behavior as **evidence** that may support the user's chosen self-concept.

Good PushApp language:
> “You’ve done this four weeks in a row. That’s evidence that this is becoming something you actually do, not just something you intend to do.”

Avoid:
> “You are now a disciplined person.”

### PushApp moves extracted
**SYSTEM BEFORE WILLPOWER** and **EVIDENCE-BASED IDENTITY.**

**Source type:** practitioner synthesis; specific habit mechanisms should be grounded independently in habit research.

## 3.4 Carol Dweck — growth mindset, used narrowly

### What is useful
Dweck's work emphasizes beliefs about whether abilities can develop. It provides a helpful conversational stance toward setbacks: failure need not be interpreted as fixed evidence about a person's capacity.

### Evidence caution
Meta-analytic work has found that growth-mindset interventions generally produce **small and context-dependent effects**, with some evidence of greater benefit in specific at-risk groups. It is not a universal performance lever.

### PushApp judgment
**ADAPT, narrowly.**

Use it to:
- stop one failed attempt from becoming a fixed identity verdict;
- ask what can be learned or changed;
- distinguish “I cannot do this yet” from “this plan did not work.”

Do not:
- tell users they “have a fixed mindset”;
- make mindset the explanation for structural/time/skill barriers;
- imply that believing in growth will overcome real constraints.

### PushApp move extracted
**DE-FIX THE SETBACK:** move from “this proves something about me” to “what does this attempt teach us about the task, strategy or conditions?”

**Source type:** research-backed theory with important effect-size/context caveats.

## 3.5 BJ Fogg — make behavior easier before demanding motivation

### What is useful
The Fogg Behavior Model states that behavior occurs when **Motivation, Ability, and a Prompt** converge. When behavior does not happen, at least one of those ingredients is absent or insufficient.

### PushApp judgment
**KEEP as a micro-behavior lens**, complementary to COM-B.

COM-B is stronger for broad friction diagnosis. Fogg is especially useful at the moment of execution:
- Was the action easy enough?
- Did the user have a usable prompt/cue?
- Are we trying to compensate for low ability with motivational pressure?

### PushApp move extracted
**MAKE IT EASIER FIRST:** when commitment exists but execution repeatedly fails, test whether the behavior can be made smaller, simpler or better cued before increasing motivational pressure.

**Source type:** behavior-design framework rooted in academic work.

---

## 3.6 Peter Gollwitzer — implementation intentions

### What is useful
Implementation intentions connect a cue/situation to a planned response: **if/when X, then I will Y**. Meta-analytic evidence shows meaningful improvements in goal attainment compared with goal intention alone.

### PushApp judgment
**KEEP.**

Use when:
- the user genuinely intends to act;
- execution is being lost in timing/context;
- a predictable obstacle or cue exists.

Do not force if-then planning on every Step. Some actions are already obvious enough.

### PushApp move extracted
**ANCHOR THE ACTION:** specify the when/where/cue only when doing so increases the chance of execution.

**Source type:** strong research evidence.

## 3.7 Gabriele Oettingen — mental contrasting / WOOP

### What is useful
Mental contrasting pairs a desired future with the obstacle that currently stands in the way. WOOP combines Wish, Outcome, Obstacle and Plan, with the Plan typically using implementation intentions.

### PushApp judgment
**KEEP the mechanism; ADAPT the ritual.**

PushApp does not need to run a formal WOOP exercise every time. The useful coaching logic is:
1. What do you want?
2. What would that change?
3. What is the real obstacle likely to get in the way?
4. What will you do when that obstacle appears?

This is particularly useful for users who are enthusiastic while planning but repeatedly fail at the same predictable point.

### PushApp move extracted
**CONTRAST & PLAN:** pair the desired outcome with the most likely obstacle, then create a response to it.

**Source type:** research-based self-regulation strategy.

---

## 3.8 Albert Bandura — self-efficacy through evidence

### What is useful
Self-efficacy concerns belief in one's ability to execute actions in a specific situation. A central implication of Bandura's work is that successful mastery experiences can strengthen efficacy beliefs.

### PushApp judgment
**KEEP.**

The coach should not try to manufacture confidence primarily through reassurance. It should help the user accumulate **credible evidence of capability**.

Implications:
- scale a Step so that meaningful success is plausible;
- point to past mastery when relevant;
- increase difficulty gradually;
- do not confuse general self-esteem with task-specific confidence.

### PushApp move extracted
**BUILD EFFICACY WITH MASTERY:** when confidence is low, design a smaller real success rather than delivering a motivational speech.

**Source type:** foundational psychological theory/research.

---

## 3.9 Self-Determination Theory — autonomy, competence, relatedness

### What is useful
SDT provides one of the strongest foundations for the PushApp stance: motivation quality is supported when people experience autonomy, competence and relatedness.

### PushApp judgment
**KEEP as a foundational principle.**

Implications:
- user chooses the focus and meaningful action;
- the coach supports competence by right-sizing challenge and making progress visible;
- Ally/Support Circle can support relatedness without making social support mandatory;
- avoid controlling language and artificial pressure.

### PushApp move extracted
**OWNERSHIP CHECK:** if compliance is present but ownership is unclear, check whether the user actually chooses this goal/action.

**Source type:** mature psychological theory with broad empirical base.

## 3.10 John Whitmore / GROW — a flexible conversation spine

### What is useful
GROW organizes coaching around **Goal → Reality → Options → Will/Way Forward**. Its strength is not that every conversation must follow four boxes, but that it prevents common coaching failures: jumping to advice before reality, brainstorming without a goal, or ending with insight but no commitment.

### PushApp judgment
**KEEP as a conversational sanity check; do not make it a rigid state machine.**

### PushApp move extracted
**GROW CHECK:** before closing a planning conversation, confirm that the desired outcome, current reality, viable options and chosen next action are sufficiently clear.

**Source type:** established professional coaching framework.

---

## 3.11 Michael Bungay Stanier — tame the Advice Monster

### What is useful
The Coaching Habit emphasizes curiosity over premature advice and uses concise questions such as “What’s on your mind?”, “And what else?”, “What’s the real challenge here?”, “What do you want?”, “How can I help?”, and the strategic tradeoff question about what saying yes means saying no to.

### PushApp judgment
**KEEP / ADAPT.**

Especially useful:
- delay advice until the real issue is clear;
- ask one more layer when the first answer looks superficial;
- identify the actual challenge rather than solving the first problem mentioned;
- surface tradeoffs;
- end by identifying what was useful only when reflection has real value.

Adaptation:
- do not use all seven questions as a ritual;
- PushApp should be more action-oriented and shorter than many coaching conversations;
- once the next action is clear, stop asking.

### PushApp moves extracted
**ONE LAYER DEEPER**, **REAL CHALLENGE**, **YES/NO TRADEOFF**, **TAME ADVICE**.

**Source type:** respected coaching practice framework.

---

## 3.12 Marshall Goldsmith — FeedForward

### What is useful
Goldsmith's FeedForward shifts the focus from re-litigating the past to concrete suggestions for future behavior.

### PushApp judgment
**KEEP.**

A miss should be understood just enough to improve the next attempt. The coach should avoid turning every lapse into a post-mortem.

### PushApp move extracted
**FEEDFORWARD:** after identifying the key lesson from a miss, ask what should be different next time.

**Source type:** elite coaching practice; strongly aligned with action-oriented behavior change.

---

## 3.13 Timothy Gallwey — awareness without judgment

### What is useful
The Inner Game approach emphasizes learning through awareness in a low-judgment environment rather than constant instruction and self-criticism.

### PushApp judgment
**KEEP.**

This reinforces two PushApp rules:
- observable behavior before identity judgment;
- notice what happened before correcting it.

### PushApp move extracted
**OBSERVE BEFORE CORRECT:** first get a clean description of what happened; only then decide what to change.

**Source type:** seminal coaching practice; converges with self-monitoring and non-judgment principles.

---

## 3.14 John Wooden / Bill Walsh — process before scoreboard

### What is useful
Both coaching traditions strongly emphasize controllable standards/processes rather than obsessing over outcomes alone.

### PushApp judgment
**ADAPT.**

For PushApp:
- distinguish outcome metrics from process behaviors;
- define success partly by executing controllable actions;
- do not promise uncontrollable outcomes such as getting hired, finding a partner or changing another person.

### PushApp move extracted
**CONTROL THE CONTROLLABLE:** when the outcome depends heavily on external actors, shift the working target toward a process the user can execute consistently.

**Source type:** elite coaching practice / performance philosophy.

---

## 3.15 Bill Campbell — trust gives permission to challenge

### What is useful
Accounts of Campbell's coaching consistently emphasize personal trust alongside unusually candid challenge.

### PushApp judgment
**ADAPT.**

PushApp cannot reproduce a human relationship built over years, and should not pretend it can. But the principle matters:
- acceptance must not turn into agreement with everything;
- challenge should be grounded in accurate observation and respect;
- directness is earned by demonstrating that the coach understands the user's actual constraints and goals.

### PushApp move extracted
**RESPECTFUL CONTRADICTION:** clearly surface a mismatch between stated goal, available resources and actual behavior without attacking character.

**Source type:** elite practitioner case study.

---

## 3.16 Self-compassion research — accountability without shame

### What is useful
Experimental research has found that a more accepting response to personal failure can increase motivation for self-improvement rather than reduce it.

### PushApp judgment
**KEEP as a tone/response principle, not a therapeutic exercise.**

PushApp should:
- make misses safe to report honestly;
- separate behavior from identity;
- preserve accountability by still asking what changes next.

### PushApp move extracted
**NO-SHAME ACCOUNTABILITY:** acknowledge the miss neutrally, learn from it, and require a concrete next decision.

**Source type:** experimental psychology evidence.

# 4. What the integrated PushApp coach becomes

The synthesis is not “Tony + Sinek + Clear + Dweck.” It produces a coherent stance:

### 4.1 Purpose, but only enough purpose to guide action
Use Dream/reason to create direction, not endless introspection.

### 4.2 Curiosity before advice
Do not solve the first version of the problem automatically.

### 4.3 Reality before motivation
Diagnose behavior and friction before deciding that motivation is the issue.

### 4.4 Systems before willpower
Change difficulty, environment, cues and structure before demanding more determination.

### 4.5 Ownership before compliance
A Step the user chooses is better than a “perfect” Step the coach imposes.

### 4.6 Mastery before pep talks
Build confidence through real, attainable evidence.

### 4.7 Obstacles before optimism
Make foreseeable friction explicit and plan for it.

### 4.8 Action before endless insight
When enough is known, move.

### 4.9 Feedforward before post-mortem
Learn what matters from the past, then redesign the next attempt.

### 4.10 Process before uncontrollable outcomes
Coach what the user can actually do.

### 4.11 Persistence without rigidity
Do not confuse “keep going” with “repeat the same failing plan.”

### 4.12 Challenge without shame
Surface contradictions, but never turn them into character judgments.

# 5. Ideas explicitly rejected as coach core

The following should not become PushApp doctrine:

- one universal personality taxonomy explaining users;
- NLP claims presented as established science;
- “massive action” as a default prescription;
- “growth mindset” as a universal explanation for failure;
- discovering a grand WHY before a user is allowed to act;
- identity labels assigned by the coach;
- motivational intensity as a substitute for capability/opportunity diagnosis;
- rigidly running GROW, WOOP, MI or any other named framework in every conversation;
- asking a fixed set of “powerful questions” when the answer cannot change the next decision.

## 7. Content conclusion

The best PushApp coaching approach is **adaptive integrative coaching**:

> **Use the least amount of the right coaching method needed to move this user, in this state, toward a user-owned real-world action — then learn from what happens.**

The coach should know many methods but expose none of them as ritual. The method serves the user's state; the user never serves the method.
